# Lab 01: Data Quality Framework — Interview Questions

## FAANG-Style Questions

1. **Design a data quality monitoring system** for a petabyte-scale data lake. How do you prioritize which checks to run?

2. **How would you detect data drift** in a production ML feature pipeline? Compare statistical vs rule-based approaches.

3. **What's the difference between schema-on-read and schema-on-write**? Which is better for a data quality framework?

4. **Design a system to validate 10,000 tables daily** within a 4-hour SLA. How do you parallelize checks?

5. **How do you handle late-arriving data** in a quality framework? What about out-of-order events?

6. **Compare Great Expectations, Deequ, and custom rules**. When would you build vs buy?

7. **How do you compute a composite data quality score** across 50 dimensions? How do you weight them?

8. **Design an alerting system** for data quality failures. How do you prevent alert fatigue?

9. **How would you validate at-least-once vs exactly-once semantics** in a pipeline using data quality checks?

10. **What metrics would you track** to measure the effectiveness of a data quality team?

11. **How do you handle PII detection** as part of data quality validation?

12. **Design a data quality SLA** for a real-time dashboard pipeline. What metrics matter?

13. **How would you implement column-level lineage** from quality check results?

14. **Compare row-level vs table-level quality checks**. When is each appropriate?

15. **How do you test a data quality framework itself**? What's the meta-quality strategy?
