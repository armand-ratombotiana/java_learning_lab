# Cracking the Interview Guide

## Strategy Overview

### Phase 1: Preparation (8–12 weeks)
- **Week 1–2**: Pick your target companies, research their process.
- **Week 3–6**: LeetCode topic-by-topic (Arrays → Linked Lists → Trees → Graphs → DP).
- **Week 7–8**: System Design (study 10 common designs, practice whiteboarding).
- **Week 9–10**: Behavioral stories (5–6 STAR stories), mock interviews.
- **Week 11–12**: Company-specific deep dive, apply, schedule interviews.

### Phase 2: Application
- **Referrals**: Best conversion rate → get internal referrals.
- **Recruiters**: LinkedIn outreach, optimize profile.
- **Direct Apply**: Last resort, but still worth doing.

### Phase 3: Interview Rounds

#### Coding Rounds
- **0–2 min**: Clarify problem, ask about inputs/outputs/edge cases.
- **2–5 min**: Discuss approach, time/space complexity, trade-offs.
- **5–30 min**: Code with clean variable names, edge cases.
- **30–35 min**: Test with example, trace through code.
- **35–40 min**: Optimize, discuss follow-ups.

#### System Design Rounds
- **0–3 min**: Gather requirements (functional + non-functional).
- **3–8 min**: Estimation (QPS, storage, bandwidth).
- **8–15 min**: High-level design (diagram, components).
- **15–35 min**: Deep dive (data model, scaling, caching, consistency).
- **35–40 min**: Trade-offs, bottlenecks, alternative designs.

#### Behavioral Rounds
- **0–2 min**: Listen to the question, ask for clarification.
- **2–5 min**: Deliver STAR story with confidence.
- **5–7 min**: Tie back to company values.
- **7–10 min**: Ask thoughtful questions.

### Phase 4: Post-Interview
- **Same day**: Send thank-you email to recruiter.
- **48 hrs**: If no response, follow up politely.
- **1 week**: Start debrief with yourself — what went well, what to improve.
- **Offer stage**: Negotiate (competing offers > leverage).

## Key Mindset
- **It's a marathon, not a sprint**: Consistent 1–2 hrs/day beats weekend binges.
- **Quantity → Quality**: 150 well-understood problems > 500 rushed problems.
- **Iterate**: Revisit problems you struggled with after 1–2 weeks.
- **Teach**: Explain problems to peers (rubber duck debugging).
- **Rejection is normal**: Learn from it, adjust, apply again.
