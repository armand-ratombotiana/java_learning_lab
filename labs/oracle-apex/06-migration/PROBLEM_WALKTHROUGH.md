# Problem Walkthrough: Migration

## Problem 1: Migrating Oracle Forms to APEX — Oracle
### APEX Interview Scenario
"Oracle is migrating a legacy Oracle Forms inventory application to APEX. Identify key migration challenges."

### Problem
Convert a Forms-based Inventory Management system (20+ canvases, 50+ data blocks) into an APEX application.

### Solution Walkthrough
1. **Analyze Forms Structure** — Document each form, block, trigger (WHEN-NEW-RECORD-INSTANCE, POST-QUERY, etc.)
2. **Map to APEX**:
   - Forms Data Block → Interactive Report + Form page
   - Control Block → Static Content region with items
   - Menu → Navigation menu / Tabs
   - Triggers → Dynamic Actions, Processes, Computations
3. **SQL Conversion** — Convert Forms PL/SQL to APEX PL/SQL
4. **Logic Migration** — Move business logic to database packages
5. **UI Redesign** — Replace Forms canvas with APEX template
6. **Validation** — Forms level-0/1/2 validations → APEX validations + constraints
7. **Data Migration** — Create scripts to migrate master/lookup data
8. **Testing** — Parallel run, compare results for 100 transaction types

### Code
```sql
-- Sample Forms-to-APEX conversion
-- Before (Forms): SET_ITEM_PROPERTY('inventory.block.quantity', ENABLED, PROPERTY_FALSE);
-- After (APEX): Dynamic Action → Set "Read Only" condition on P1_QUANTITY

-- Forms POST-QUERY trigger
-- Original: SELECT description INTO :item.description FROM products WHERE product_id = :item.product_id;
-- APEX: Add to report query directly
SELECT i.item_id, p.description, i.quantity
FROM items i
JOIN products p ON p.product_id = i.product_id;
```

### Company Evaluation
- **Oracle**: Forms-to-APEX migration methodology, Forms API equivalence
- **Deloitte**: Migration assessment, business case for modernization
- **Accenture**: Large-scale migration factory approach, automated conversion tools

## Problem 2: Data Migration from Legacy Tables — Deloitte
### APEX Interview Scenario
"Deloitte's client is migrating from a legacy ERP to Oracle with APEX frontend. Extract, transform, and load legacy data."

### Problem
Migrate 500K customer records from a legacy system (CSV/JSON) into Oracle APEX application tables.

### Solution Walkthrough
1. **Source Analysis** — Map legacy fields to APEX app columns:
   ```
   Legacy: CUST_NO, NAME, ADDR1, ADDR2, CITY, ZIP, PHONE
   APEX:   customer_id, full_name, address_line1, address_line2, city, postal_code, phone
   ```
2. **Staging Table** — Load raw data into `CUSTOMERS_STAGING`
3. **Data Cleansing** — SQL transformations:
   ```sql
   UPDATE customers_staging
   SET zip = LPAD(zip, 5, '0')
   WHERE LENGTH(zip) < 5;
   ```
4. **Duplicate Detection** — Check existing customers
5. **Load to Production**:
   ```sql
   INSERT INTO customers (customer_id, full_name, address_line1, city, postal_code, phone)
   SELECT customer_seq.NEXTVAL, TRIM(name), ADDR1, CITY, ZIP, PHONE
   FROM customers_staging s
   WHERE NOT EXISTS (SELECT 1 FROM customers c WHERE c.full_name = TRIM(s.name));
   ```
6. **APEX Data Load Wizard** — Use "Data Workshop" → "Load Data" for manual loads
7. **Validation Report** — Counts of loaded, skipped, errored records

### Code
```sql
-- Staging table
CREATE TABLE customers_staging (
    raw_id    NUMBER GENERATED BY DEFAULT AS IDENTITY,
    cust_no   VARCHAR2(20),
    name      VARCHAR2(200),
    addr1     VARCHAR2(200),
    addr2     VARCHAR2(200),
    city      VARCHAR2(100),
    zip       VARCHAR2(20),
    phone     VARCHAR2(30),
    load_date DATE DEFAULT SYSDATE,
    status    VARCHAR2(20) DEFAULT 'NEW'
);

-- Validation check
SELECT status, COUNT(*) AS record_count
FROM customers_staging
GROUP BY status;
```

### Company Evaluation
- **Deloitte**: Data governance, quality checks, reconciliation reports
- **Accenture**: ETL automation, scheduling, error handling
- **Oracle**: Oracle SQL*Loader, external tables, Data Pump

## Problem 3: Upgrading APEX Application Version — Accenture
### APEX Interview Scenario
"Accenture needs to upgrade a client's APEX app from 19.2 to 23.1. Plan the upgrade."

### Problem
Enterprise APEX application running on 19.2. Target: 23.1 (major version jump). Need to test all regression areas.

### Solution Walkthrough
1. **Pre-Upgrade Check** — Run `APEX_PREUPGRADE_CHECK.sql` on 19.2 instance
2. **Review Deprecations** — Check APEX 21.1, 22.1, 23.1 release notes
3. **Backup** — Full database export, APEX application export
4. **Test Environment** — Clone PROD, upgrade clone first
5. **Upgrade Steps**:
   - Upgrade APEX on middle tier (ORDS)
   - Copy new APEX files to ORDS webapps
   - Run `apxremov.sql` then `apxchpss.sql` (or full upgrade)
6. **Application Testing Checklist**:
   - All Interactive Reports render correctly
   - Dynamic Actions still fire (new JavaScript engine)
   - Chart libraries (Oracle JET version update)
   - Template compatibility
7. **Performance Regression** — Run baseline queries, compare explain plans
8. **Rollback Plan** — Keep pre-upgrade database snapshot

### Code
```sql
-- Pre-upgrade check commands
@apex/utilities/preupgrade/APEX_PREUPGRADE_CHECK.sql

-- Check current version
SELECT version_no, patch_min, patch_max
FROM APEX_RELEASE;

-- Post-upgrade validation
SELECT application_id, application_name, status
FROM APEX_APPLICATIONS
WHERE application_id = 100;
```

### Company Evaluation
- **Accenture**: Upgrade methodology, regression testing, rollback planning
- **Deloitte**: Client communication, downtime scheduling
- **Oracle**: Internal APEX upgrade algorithms, metadata compatibility

## Problem 4: Database Schema & APEX Application Migration — Oracle
### APEX Interview Scenario
"Oracle's customer needs to move an APEX application from on-premises to Oracle Cloud (Autonomous Database)."

### Problem
Migrate APEX app and all schema objects from on-prem Oracle 19c to Oracle Autonomous Database (ADW).

### Solution Walkthrough
1. **Export Schema** — Use Data Pump:
   ```bash
   expdp user/pass schemas=APP_SCHEMA directory=DATA_PUMP_DIR dumpfile=app.dmp
   ```
2. **Export APEX App** — Via APEX Builder: Export application `f100.sql`
3. **Upload to Object Storage** — Upload dump to OCI Object Storage bucket
4. **Import into ADW** — Use Data Pump on ADW:
   ```bash
   impdp admin/pass@adw_high schemas=APP_SCHEMA dumpfile=app.dmp
   ```
5. **Install APEX App** — Run `f100.sql` on ADW instance
6. **Reset Passwords** — Update workspace and schema passwords
7. **Configure ORDS** — Enable ORDS on ADW for APEX access
8. **Update Connections** — Change database links, ACLs
9. **Test** — End-to-end testing on new ADW instance

### Code
```sql
-- Check APEX version compatibility with ADW
SELECT * FROM V$VERSION;

-- Validate schema objects after import
SELECT object_type, COUNT(*)
FROM user_objects
WHERE status = 'VALID'
GROUP BY object_type;

-- Recompile invalid objects
BEGIN
    DBMS_UTILITY.COMPILE_SCHEMA('APP_SCHEMA');
END;
/
```

### Company Evaluation
- **Oracle**: Autonomous Database features, Data Pump, APEX on ADW
- **Accenture**: Cloud migration playbook, cost analysis, migration tools
- **Deloitte**: Business continuity, migration timeline, stakeholder reporting
