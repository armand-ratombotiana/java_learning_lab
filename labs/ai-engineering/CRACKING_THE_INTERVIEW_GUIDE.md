# Cracking the Interview Guide

## The Overall Strategy

### Phase 1: Foundation (Weeks 1-4)
- **Goal**: Build algorithmic fluency
- **Daily**: 2 LeetCode problems (Easy/Medium)
- **Weekly**: 1 system design whiteboard practice
- **Focus**: Arrays, Strings, HashMaps, Two Pointers, Sliding Window
- **Resource**: NeetCode 150 (focus on first 50 problems)

### Phase 2: Depth (Weeks 5-8)
- **Goal**: Master core AI engineering topics
- **Daily**: 1 LeetCode problem (Medium) + read 1 AI engineering blog
- **Weekly**: 1 ML system design problem
- **Focus**: Trees, Graphs, DP, Backtracking
- **AI Focus**: Transformer architecture, RAG, vector search, agent frameworks

### Phase 3: Integration (Weeks 9-12)
- **Goal**: Combine all skills in interview setting
- **Daily**: Timed LeetCode (1 Medium in 30 min)
- **Weekly**: 2-3 mock interviews (peer or recorded)
- **Focus**: Full-system design, behavioral storytelling
- **AI Focus**: Production AI systems, deployment, observability, security

### Phase 4: Company-Specific (Weeks 13-14)
- **Goal**: Tailor preparation to target companies
- **Research**: Company AI stack, products, recent papers
- **Practice**: Company-specific question banks (LeetCode company tags)
- **Behavioral**: Refine STAR stories for company-specific values

## The Interview Day Checklist

### Before
- [ ] Review your STAR stories (10 prepared answers)
- [ ] Review system design templates (LLM serving, RAG, agents)
- [ ] Review common time/space complexities
- [ ] Test your setup (camera, mic, internet, IDE)
- [ ] Sleep well, eat light, hydrate

### During
- [ ] **First 2 minutes**: Clarify the problem, ask about constraints
- [ ] **Next 3 minutes**: Propose approach, discuss trade-offs
- [ ] **Next 20 minutes**: Code — clear, organized, well-named variables
- [ ] **Next 5 minutes**: Test — walk through example, edge cases
- [ ] **Optimize**: Discuss time/space complexity improvements

### After Each Round
- [ ] Thank the interviewer
- [ ] Ask 1-2 thoughtful questions about the team/product
- [ ] Take notes on what went well and what to improve

## Common Pitfalls

### Coding
- Not clarifying constraints before coding
- Writing code without discussing approach first
- Ignoring edge cases (empty input, null, negative numbers)
- Not testing with examples after writing
- Giving up too early — ask for hints, keep talking

### System Design
- Jumping into details without requirements clarification
- Ignoring scale (QPS, storage, bandwidth estimates)
- Not discussing trade-offs between alternatives
- Forgetting about monitoring, deployment, failure modes
- Over-engineering the solution for the given constraints

### Behavioral
- Stories without measurable results
- Being too vague — use specific numbers and names
- Not connecting story to the question asked
- Sounding rehearsed — be natural and conversational
